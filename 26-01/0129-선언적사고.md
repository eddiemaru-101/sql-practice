> 일단 조건부터 파악하자.  
> 1.급여가 30,000원 이하인 직원을 필터링하고  
> 2. manger_id의 직원이 없는 사람을 필터링해서 출력하자!

```
< : less than (미만)
<= : less than or equal to (이하)
> : greater than (초과)
>= : greater than or equal to (이상)
```
<br><br>

## 1단계 - 급여조건 필터링

```
SELECT
employee_id
,manager_id
FROM Employees
WHERE salary <= 30000;

| employee_id | manager_id |
| ----------- | ---------- |
| 1           | 11         |
| 11          | 6          |
```
<br><br>


## 2단계 - 매니저가 퇴사한 사람 필터링  
> 어떻게 해야할지 고민하다가 RIGHT JOIN해서 null인 사람 걸러내면 되겠구나 감을 잡음.  
> 몇번의 수정을 거처서 완성했다.

```
WITH low_salary AS (
    SELECT
    employee_id
    ,manager_id
    FROM Employees
    WHERE salary < 30000
        AND manager_id IS NOT NULL
)
SELECT
    l1.employee_id
FROM Employees e1
RIGHT JOIN low_salary l1
ON l1.manager_id = e1.employee_id
WHERE e1.employee_id IS NULL
ORDER BY l1.employee_id ASC;

| employee_id |
| ----------- |
| 11          |
```
<br><br>

## 3단계 - 쿼리 튜닝 개선 
> 헉, 그냥 left조인만으로 풀 수 있었다.
> CTE를 안써도됨 
- CTE안쓰고 LEFT조인 적용
  - CTE는 가독성은 좋은데, MySQL 5.7 이하에서는 임시 테이블 생성 → 추가 I/O
  - MySQL 8.0+에서는 optimizer가 CTE를 inline으로 최적화하기도 함 → 써도 별차이 없다는 뜻  
```
SELECT e1.employee_id
FROM Employees e1
LEFT JOIN Employees e2 ON e1.manager_id = e2.employee_id
WHERE e1.salary < 30000
  AND e1.manager_id IS NOT NULL
  AND e2.employee_id IS NULL
ORDER BY e1.employee_id;
```
<br><br>


## 4단계 - 문제접근방법 복기  

### '절차적 사고(Procedural Thinking)'
- 내가 CTE로 접근한 이유 (사고 과정 분석)
1단계 : 문제를 순차적으로 읽음
```
1. "급여 30000 미만인 직원"
   → 아, 먼저 이 사람들 찾아야겠다
   
2. "그리고 매니저가 퇴사한"
   → 그 다음에 이 조건 체크해야겠다
```
<br><br><br>


### 선언적 사고(Declarative Thinking)
- "문제를 다시 보되, 단계가 아닌 관계로 생각해보자:
```
"나는 이런 특성을 가진 데이터를 원한다"
→ 모든 조건을 한 번에 기술
```
<br>

**Step 1: 엔티티 관계 파악**
```
문제: "급여 30000 미만이고 매니저가 퇴사한 직원"

핵심 관계:
- 직원(Employee) ←→ 매니저(Manager)
- 매니저도 Employees 테이블에 있음 (Self-Referencing)
```

이 순간 떠올려야 할 것:
> '아, 이건 Self-Join 문제구나'
```
Employees e1  -- 직원 관점
Employees e2  -- 매니저 관점
```
<br><br>

**Step 2: 조인 조건 설계**
- "직원의 manager_id와 매니저의 employee_id를 연결"
```
e1.manager_id = e2.employee_id
```
이때 질문:
'매니저가 퇴사했다 = 매니저 정보가 없다'
→ LEFT JOIN 후 e2가 NULL인 케이스
```
FROM Employees e1
LEFT JOIN Employees e2 ON e1.manager_id = e2.employee_id
```
<br><br>

**Step 3: 필터 조건 추가**
```
이제 WHERE 절로 조건들 나열:

1. e1.salary < 30000  -- 급여 조건
2. e1.manager_id IS NOT NULL  -- 애초에 매니저 있었던 사람
3. e2.employee_id IS NULL  -- 매니저 퇴사 (조인 실패)
```

```
-- 생각의 흐름:
"나는 이런 데이터를 원한다:"

SELECT e1.employee_id
FROM Employees e1  -- 직원
LEFT JOIN Employees e2 ON e1.manager_id = e2.employee_id  -- 매니저와 연결
WHERE 
  e1.salary < 30000  -- 조건1
  AND e1.manager_id IS NOT NULL  -- 조건2
  AND e2.employee_id IS NULL  -- 조건3
```

# 1978. Employees Whose Manager Left the Company
```
Table: Employees

+-------------+----------+
| Column Name | Type     |
+-------------+----------+
| employee_id | int      |
| name        | varchar  |
| manager_id  | int      |
| salary      | int      |
+-------------+----------+
In SQL, employee_id is the primary key for this table.
This table contains information about the employees, their salary, and the ID of their manager. Some employees do not have a manager (manager_id is null). 
 

Find the IDs of the employees whose salary is strictly less than $30000 and whose manager left the company. When a manager leaves the company, their information is deleted from the Employees table, but the reports still have their manager_id set to the manager that left.

Return the result table ordered by employee_id.

The result format is in the following example.

 

Example 1:

Input:  
Employees table:
+-------------+-----------+------------+--------+
| employee_id | name      | manager_id | salary |
+-------------+-----------+------------+--------+
| 3           | Mila      | 9          | 60301  |
| 12          | Antonella | null       | 31000  |
| 13          | Emery     | null       | 67084  |
| 1           | Kalel     | 11         | 21241  |
| 9           | Mikaela   | null       | 50937  |
| 11          | Joziah    | 6          | 28485  |
+-------------+-----------+------------+--------+
Output: 
+-------------+
| employee_id |
+-------------+
| 11          |
+-------------+

Explanation: 
The employees with a salary less than $30000 are 1 (Kalel) and 11 (Joziah).
Kalel's manager is employee 11, who is still in the company (Joziah).
Joziah's manager is employee 6, who left the company because there is no row for employee 6 as it was deleted.

```
