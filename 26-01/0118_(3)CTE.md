> null조건이 있어서 어려울것 같은 느낌이 든다.  

<br>

- 문제해석
```
A single number is a number that appeared only once in the MyNumbers table.
- A single number란 MyNumbers 테이블에서 한 번만 등장한 숫자를 의미한다.

If there is no single number, report null.
- 싱글넘버가 없으면 null을 반환해라.
```

## 1단계 - null조건 빼고 작성하기  
> 어라.. 내 예상대로 안나오네, 원인을 분석해보자! 
> 집계함수는 그 기준 행만(그룹별로 적용) 기준으로 함수를 적용해서 그렇다.
> 기준 행이 다르면 크기를 비교하지 못한다.
> ORDER BY는 SELECT치고 적용하니까 적합하지않고, SELECT문에서 수정해야하나? 서브쿼리로 해야하나?
> 인덱싱이 되나? 흠..  
```
SELECT
    MAX(num) AS num
FROM MyNumbers
GROUP BY num
HAVING COUNT(num)=1;

<result>
| num |
| --- |
| 1   |
| 4   |
| 5   |
| 6   |
```
<br>

## 2단계 - 서브쿼리로 풀기
> 서브쿼리 테이블로 사용하면 레코드간의 집계함수로 사용할 수 있다.

- 정답쿼리 
```
SELECT MAX(num) AS num
FROM (
    SELECT num
    FROM MyNumbers
    GROUP BY num
    HAVING COUNT(num)=1 ) AS single_mynumbers;

<result>
| num |
| --- |
| 6   |

```
> 근데 null처리는 안했는데?  

<br>

## 3단계 - null, 다른접근법 
> null처리는 자동으로 MAX(num)에서 숫자가 없으면 null처리된다.  
> FROM절에 서브쿼리를 쓴건 처음인데 with문으로 표현하는 거 보자  
- **MAX()의 특성:**
  - 결과가 없으면 자동으로 NULL 반환
  - 별도 처리 불필요

### CTE(Common Table Expression)
- **정의**
  - with문을 사용해서 임시 결과 집합에 이름을 붙이는 것
```
-- 일반 형태
WITH 임시테이블명 AS (
    SELECT ...
)
SELECT ...
FROM 임시테이블명;
```
> FROM절에 서브쿼리로 표현해도 되는데  
> 왜 WITH문으로 따로 빼서 사용할까?  
<br>

- **배경**
  - 서브쿼리 지옥  
```
-- 보기 힘든 괴물같은 쿼리들..

SELECT a.dept, a.avg_salary
FROM (
    SELECT dept, AVG(salary) as avg_salary
    FROM (
        SELECT e.dept, e.salary
        FROM employees e
        WHERE e.status = 'active'
    ) AS active_emp
    GROUP BY dept
) AS a
WHERE a.avg_salary > (
    SELECT AVG(salary) * 1.2
    FROM (
        SELECT salary
        FROM employees
        WHERE status = 'active'
    ) AS all_active
);
```
> "이거 보면 머리 아프지? 같은 서브쿼리를 여러 번 반복하고, 괄호 안에 괄호...
> 한참 뒤에 보면 내가 작성한 쿼리인데도 못 읽음. 유지보수도 힘듬"

<br>

- 수정된 방식
  - 순차적으로 읽으면 되고 편함
```
-- "자, 이렇게 쓰면 훨씬 깔끔해."
WITH order_amounts AS (
    -- Step 1: 각 주문의 총액 계산
    SELECT 
        o.user_id,
        o.order_id,
        SUM(oi.price * oi.quantity) as amount
    FROM orders o
    JOIN order_items oi ON o.order_id = oi.order_id
    WHERE o.created_at >= DATE_SUB(NOW(), INTERVAL 1 YEAR)
    GROUP BY o.user_id, o.order_id
),
user_stats AS (
    -- Step 2: 유저별 통계 계산
    SELECT 
        user_id,
        COUNT(*) as total_orders,
        SUM(amount) as total_spent,
        AVG(amount) as avg_order_value
    FROM order_amounts
    GROUP BY user_id
)
-- Step 3: 등급 매기기
SELECT 
    user_id,
    total_orders,
    total_spent,
    avg_order_value,
    CASE 
        WHEN total_spent > 10000 THEN 'VIP'
        WHEN total_spent > 5000 THEN 'Gold'
        ELSE 'Regular'
    END AS tier
FROM user_stats
ORDER BY total_spent DESC;
```
<br> 


- **다른 장점**
- 평균보다 높은 급여계산 예시 쿼리

```
# 서브쿼리 방식
SELECT 
    name,
    salary,
    salary - (SELECT AVG(salary) FROM employees) AS diff_from_avg
FROM employees
WHERE salary > (SELECT AVG(salary) FROM employees);
-- 평균 급여를 2번 계산
-- "평균 급여 계산을 2번 해. 완전 낭비지."


# CTE 방식
WITH avg_salary AS (
    SELECT AVG(salary) AS avg_sal
    FROM employees
)
SELECT 
    e.name,
    e.salary,
    e.salary - a.avg_sal AS diff_from_avg
FROM employees e
CROSS JOIN avg_salary a
WHERE e.salary > a.avg_sal;
-- 평균 급여를 딱 1번만 계산
-- "avg_salary를 한 번 계산하고, 여러 곳에서 재사용. 효율적임"
```

## 4단계 - 정답쿼리(CTE사용)
> 아직 감은 잘 안오지만 써봐야 알듯  
- **정답쿼리**
```
WITH single_numbers AS (
    SELECT num
    FROM MyNumbers
    GROUP BY num
    HAVING COUNT(num) = 1
)
SELECT MAX(num) AS num
FROM single_numbers;
```

```
Table: MyNumbers

+-------------+------+
| Column Name | Type |
+-------------+------+

+-------------+------+
This table may contain duplicates (In other words, there is no primary key for this table in SQL).
Each row of this table contains an integer.
 

A single number is a number that appeared only once in the MyNumbers table.

Find the largest single number. If there is no single number, report null.

The result format is in the following example.

 

Example 1:

Input: 
MyNumbers table:
+-----+
| num |
+-----+
| 8   |
| 8   |
| 3   |
| 3   |
| 1   |
| 4   |
| 5   |
| 6   |
+-----+
Output: 
+-----+
| num |
+-----+
| 6   |
+-----+
Explanation: The single numbers are 1, 4, 5, and 6.
Since 6 is the largest single number, we return it.
Example 2:

Input: 
MyNumbers table:
+-----+
| num |
+-----+
| 8   |
| 8   |
| 7   |
| 7   |
| 3   |
| 3   |
| 3   |
+-----+
Output: 
+------+
| num  |
+------+
| null |
+------+
Explanation: There are no single numbers in the input table so we return null.
```
