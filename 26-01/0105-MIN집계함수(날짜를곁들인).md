> 처음부터 막혔다
> 고객의 첫 주문을 어떻게 쿼리로 표현하지?

 
## 0단계 - 막힘
> 대충 GROUP BY 하는건 알겠는데
> 첫 주문을 어떻게 할지 모르겠네.. 
```
SELECT *
FROM Delivery
```
- GROUP BY 하면 맨 첫주문만 남는다.
  - 아니네.. customer_id = 3 은 날짜가 정렬이안되어있네
  - (ORDER BY하면되는거 아니야?) -> ORDER BY는 SELECT절 다음에 실행됨(반영안됨)
```
SELECT *
FROM Delivery
GROUP BY customer_id;

| delivery_id | customer_id | order_date | customer_pref_delivery_date |
| ----------- | ----------- | ---------- | --------------------------- |
| 1           | 1           | 2019-08-01 | 2019-08-02                  |

| 4           | 3           | 2019-08-24 | 2019-08-24                  |
| 7           | 4           | 2019-08-09 | 2019-08-09                  |


Delivery table:
+-------------+-------------+------------+-----------------------------+
| delivery_id | customer_id | order_date | customer_pref_delivery_date |
+-------------+-------------+------------+-----------------------------+
| 1           | 1           | 2019-08-01 | 2019-08-02                  |
```

## 1단계 - 일단 첫 주문 쿼리 완성 
- 힌트:
  - MIN(날짜) -> 가장 빠른 날짜

```
SELECT 
    customer_id
    ,Min(order_date) AS 'earlist_date'
FROM Delivery
GROUP BY customer_id

| customer_id | earlist_date |
| ----------- | ------------ |
| 1           | 2019-08-01   |
| 2           | 2019-08-02   |
| 3           | 2019-08-21   |
| 4           | 2019-08-09   |
```

> 저 쿼리의 SELECT문을 수정해서 구하면 되겠다  
>  → 안됨. GROUP BY 사용했으면, SELECT문에서 사용하는 컬럼은 반드시 집계함수를 사용해야함.  
>    단, customer_id는 group by의 기준이라 가능함.
```
SELECT 
    customer_id,           -- ✓ GROUP BY에 있음
    MIN(order_date),       -- ✓ 집계 함수
    MAX(order_date),       -- ✓ 집계 함수
    COUNT(*),              -- ✓ 집계 함수
    AVG(delivery_id)       -- ✓ 집계 함수
FROM Delivery
GROUP BY customer_id
```

## 2단계 - 생각의 전환 
> 내가 구한 것:  
> "흠... GROUP BY로 각 고객의 MIN(order_date)는 구했는데,  
> 문제는 그 날짜에 해당하는 전체 행 정보가 필요하다는 거야.

> 특히 customer_pref_delivery_date가 필요한데,  
> 이건 집계 함수로 못 구하잖아. MIN(customer_pref_delivery_date)를 구하면   
> 그건 배송 희망일 중 최솟값이지, 첫 주문의 배송 희망일이 아니거든.

### 자기 자신의 테이블이 필요할 때 해법
- 서브쿼리 + JOIN (self조인 방식)
- WHERE IN (서브쿼리) -> 필터링
```
WHERE IN 선호하는 경우:
- 조건이 단순할 때
- 가독성이 중요할 때
- 빠르게 작성해야 할 때

JOIN 선호하는 경우:
- 서브쿼리 결과의 여러 컬럼을 메인 쿼리에서 사용할 때
- 복잡한 매칭 조건이 있을 때
- 성능 최적화가 필요할 때 (경우에 따라 JOIN이 더 빠를 수 있음)
```
### 적용하기
> 근데 문제가 컬럼 두개가 동일한 레코드를 필터링해야함!
- WHERE IN 일반적으로 한 컬럼만 매칭: 
```
WHERE customer_id IN (서브쿼리)  -- 한 컬럼만 매칭
```
- 근데 나는 customer_id랑 order_date 둘 다 매칭해야 하잖아?
- MySQL에서는 튜플 매칭이 가능해:
```
WHERE (customer_id, order_date) IN (서브쿼리)  -- 두 컬럼 페어로 매칭
```
- 적용하면,
```
SELECT *
FROM Delivery
WHERE (customer_id, order_date) IN (
    SELECT 
        customer_id
        ,Min(order_date)
    FROM Delivery
    GROUP BY customer_id
    );


| delivery_id | customer_id | order_date | customer_pref_delivery_date |
| ----------- | ----------- | ---------- | --------------------------- |
| 1           | 1           | 2019-08-01 | 2019-08-02                  |
| 2           | 2           | 2019-08-02 | 2019-08-02                  |
| 5           | 3           | 2019-08-21 | 2019-08-22                  |
| 7           | 4           | 2019-08-09 | 2019-08-09                  |
```

## 3단계 - SELECT정리
- 정답쿼리 
```
SELECT 
    COUNT(CASE WHEN order_date = customer_pref_delivery_date THEN 1 END)*100/COUNT(customer_id) AS immediate_percentage
FROM Delivery
WHERE (customer_id, order_date) IN (
    SELECT 
        customer_id
        ,Min(order_date)
    FROM Delivery
    GROUP BY customer_id
    );


| immediate_percentage |
| -------------------- |
| 50                   |

-- COUNT(CASE WHEN order_date = customer_pref_delivery_date THEN 1 END)
동작:
- delivery_id=1: 날짜 다름 → NULL → 카운트 안 됨
- delivery_id=2: 날짜 같음 → 1 → 카운트 됨
- delivery_id=5: 날짜 다름 → NULL → 카운트 안 됨
- delivery_id=7: 날짜 같음 → 1 → 카운트 됨
결과: 2
  
```
- 또는, COUNT가 아닌 SUM을 사용해도 동일함
```
SELECT 
    ROUND(
        SUM(CASE WHEN order_date = customer_pref_delivery_date THEN 1 ELSE 0 END) * 100.0 
        / COUNT(*),
        2
    ) AS immediate_percentage
FROM Delivery
WHERE (customer_id, order_date) IN (
    SELECT 
        customer_id,
        MIN(order_date)
    FROM Delivery
    GROUP BY customer_id
);


-- SUM(CASE WHEN order_date = customer_pref_delivery_date THEN 1 ELSE 0 END)
동작:
- delivery_id=1: 0
- delivery_id=2: 1
- delivery_id=5: 0
- delivery_id=7: 1
SUM(0, 1, 0, 1) = 2
  
```
- AVG트릭을 이용한 간결한 쿼리
  - AVG 트릭
    ```
    -- AVG(order_date = customer_pref_delivery_date)
    
    order_date = customer_pref_delivery_date는 TRUE(1) 또는 FALSE(0)
    - delivery_id=1: FALSE (0)
    - delivery_id=2: TRUE (1)
    - delivery_id=5: FALSE (0)
    - delivery_id=7: TRUE (1)
    AVG(0, 1, 0, 1) = 0.5
      
    ```

```
SELECT 
    ROUND(AVG(order_date = customer_pref_delivery_date) * 100, 2) AS immediate_percentage
FROM Delivery
WHERE (customer_id, order_date) IN (
    SELECT 
        customer_id,
        MIN(order_date)
    FROM Delivery
    GROUP BY customer_id
);
  
```
# 1174. Immediate Food Delivery II
```
Table: Delivery

+-----------------------------+---------+
| Column Name                 | Type    |
+-----------------------------+---------+
| delivery_id                 | int     |
| customer_id                 | int     |
| order_date                  | date    |
| customer_pref_delivery_date | date    |
+-----------------------------+---------+
delivery_id is the column of unique values of this table.
The table holds information about food delivery to customers that make orders at some date and specify a preferred delivery date (on the same order date or after it).
 

If the customer's preferred delivery date is the same as the order date, then the order is called immediate; otherwise, it is called scheduled.

The first order of a customer is the order with the earliest order date that the customer made. It is guaranteed that a customer has precisely one first order.

Write a solution to find the percentage of immediate orders in the first orders of all customers, rounded to 2 decimal places.

The result format is in the following example.

 

Example 1:

Input: 
Delivery table:
+-------------+-------------+------------+-----------------------------+
| delivery_id | customer_id | order_date | customer_pref_delivery_date |
+-------------+-------------+------------+-----------------------------+
| 1           | 1           | 2019-08-01 | 2019-08-02                  |
| 2           | 2           | 2019-08-02 | 2019-08-02                  |
| 3           | 1           | 2019-08-11 | 2019-08-12                  |
| 4           | 3           | 2019-08-24 | 2019-08-24                  |
| 5           | 3           | 2019-08-21 | 2019-08-22                  |
| 6           | 2           | 2019-08-11 | 2019-08-13                  |
| 7           | 4           | 2019-08-09 | 2019-08-09                  |
+-------------+-------------+------------+-----------------------------+
Output: 
+----------------------+
| immediate_percentage |
+----------------------+
| 50.00                |
+----------------------+
Explanation: 
The customer id 1 has a first order with delivery id 1 and it is scheduled.
The customer id 2 has a first order with delivery id 2 and it is immediate.
The customer id 3 has a first order with delivery id 5 and it is scheduled.
The customer id 4 has a first order with delivery id 7 and it is immediate.
Hence, half the customers have immediate first orders.
```
