- FROM Register r, Users u
  - 이게 어떻게 작동하는지 이해 못했음
  - 이건 카테시안곱으로 처리하는 코드임
  - 그래서 결과가 100,100,100,100 퍼센트로 나오는 것임
```
SELECT 
    r.contest_id
    ,ROUND((count(r.user_id)/COUNT(u.user_id))*100,2) AS percentage 
FROM Register r, Users u
GROUP BY r.contest_id;
```

### 왜 저렇게 만들었을까?
> 왜 저렇게 만들었을까? 난 그냥 두개 테이블 가져와서 각각 사용하고 싶은거였는데..
- from 절에 테이블 두개 가지고 오면 카테시안곱 처리하는 이유
> 실무 독백: "처음엔 INNER JOIN이라는 키워드도 없었어. 그냥 FROM A, B WHERE 조건 이렇게만 썼지.
> Cartesian Product 만들고 WHERE로 필터링하는 게 표준이었던 거야."
초기 SQL 설계 철학:
```
"FROM절은 데이터 소스를 나열한다"
"WHERE절은 조건을 적용한다"

-- 테이블 1개
SELECT * FROM A;
-- 결과: A의 모든 row

-- 테이블 2개 (쉼표로 나열)
SELECT * FROM A, B;
-- 결과: A와 B의 모든 조합 (일관성 있는 동작)

```
> "테이블을 나열하면 → 그들의 모든 조합을 만든다"
> "조건이 필요하면 → WHERE에 써라"

**시간이 지나면서 변화**
SQL-92 표준 (1992년)
명시적 JOIN 문법 도입:
```
-- Old Style (SQL-89)
SELECT * 
FROM A, B 
WHERE A.id = B.id;


-- New Style (SQL-92)
SELECT * 
FROM A 
INNER JOIN B ON A.id = B.id;
```

- 정답쿼리
```
SELECT 
    r.contest_id
    ,ROUND((COUNT(user_id)/(SELECT COUNT(user_id) FROM Users u))*100, 2) AS percentage 
FROM Register r
GROUP BY r.contest_id
ORDER BY percentage DESC, r.contest_id ASC;

| contest_id | percentage |
| ---------- | ---------- |
| 208        | 100        |
| 209        | 100        |
| 210        | 100        |
| 215        | 66.67      |
| 207        | 33.33      |
```



# 1633. Percentage of Users Attended a Contest
```
Table: Users

+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| user_id     | int     |
| user_name   | varchar |
+-------------+---------+
user_id is the primary key (column with unique values) for this table.
Each row of this table contains the name and the id of a user.
 

Table: Register

+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| contest_id  | int     |
| user_id     | int     |
+-------------+---------+
(contest_id, user_id) is the primary key (combination of columns with unique values) for this table.
Each row of this table contains the id of a user and the contest they registered into.
 

Write a solution to find the percentage of the users registered in each contest rounded to two decimals.

Return the result table ordered by percentage in descending order. In case of a tie, order it by contest_id in ascending order.

The result format is in the following example.

 

Example 1:

Input: 
Users table:
+---------+-----------+
| user_id | user_name |
+---------+-----------+
| 6       | Alice     |
| 2       | Bob       |
| 7       | Alex      |
+---------+-----------+
Register table:
+------------+---------+
| contest_id | user_id |
+------------+---------+
| 215        | 6       |
| 209        | 2       |
| 208        | 2       |
| 210        | 6       |
| 208        | 6       |
| 209        | 7       |
| 209        | 6       |
| 215        | 7       |
| 208        | 7       |
| 210        | 2       |
| 207        | 2       |
| 210        | 7       |
+------------+---------+
Output: 
+------------+------------+
| contest_id | percentage |
+------------+------------+
| 208        | 100.0      |
| 209        | 100.0      |
| 210        | 100.0      |
| 215        | 66.67      |
| 207        | 33.33      |
+------------+------------+
Explanation: 
All the users registered in contests 208, 209, and 210. The percentage is 100% and we sort them in the answer table by contest_id in ascending order.
Alice and Alex registered in contest 215 and the percentage is ((2/3) * 100) = 66.67%
Bob registered in contest 207 and the percentage is ((1/3) * 100) = 33.33%
```
