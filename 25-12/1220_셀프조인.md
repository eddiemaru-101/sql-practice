# [leet] 197. Rising Temperature

## 1단계 - SELF JOIN(=INNER JOIN)
JOIN의 정확한 의미
JOIN은 서로 다른 테이블(또는 같은 테이블의 다른 행)을
“공통 조건을 기준으로 행 단위로 나란히 놓기만 한다"
- JOIN 자체는 “비교를 하지 않는다”
- 조건을 만족하는 행끼리 한 행으로 붙여줌
```
SELECT *
FROM weather w1
INNER JOIN weather w2
on w1.recordDate = w2.recordDate;

<result>
| id | recordDate | temperature | id | recordDate | temperature |
| -- | ---------- | ----------- | -- | ---------- | ----------- |
| 1  | 2015-01-01 | 10          | 1  | 2015-01-01 | 10          |
| 2  | 2015-01-02 | 25          | 2  | 2015-01-02 | 25          |
| 3  | 2015-01-03 | 20          | 3  | 2015-01-03 | 20          |
| 4  | 2015-01-04 | 30          | 4  | 2015-01-04 | 30          |
```

## 2단계 - SELF JOIN의 대상, DATE_ADD함수
어떤 행의 recordDate가
다른 행의 recordDate + 1일
- “w1의 날짜는 w2의 날짜보다 정확히 하루 뒤여야 한다”
```
-- w1.recordDate = w2.recordDate + 1일
-- DATE_ADD함수로 표현하기
-- DATE_ADD 함수의 역할 - +1로 하면 연,월,일,시 중에 어떤걸 1더하는지 모름, 명시적으로 지정해주는 역할을 하는 함수임
 
ON w1.recordDate = DATE_ADD(w2.recordDate, INTERVAL 1 DAY)

--DATE_ADD([기준날짜], INTERVAL [값] [단위])
```

```
--오답
SELECT *
FROM weather w1
INNER JOIN weather w2
on w1.recordDate = DATE_ADD(w1.recordDate, INTERVAL +1 DAY);

-- JOIN인데 동일한 테이블의 조건을 기입함
-- w1.recordDate = DATE_ADD(w1.recordDate, INTERVAL +1 DAY); 

-- 수정
```

## 3단계 - 조건절
- 여기서 멘붕이 시작됨
- `on w1.recordDate = DATE_ADD(w2.recordDate, INTERVAL +1 DAY)`
- 이제 w1(어제), w2(오늘) 이겠지? 라고 생각하고
- ` WHERE w1.temperature < w2.temperature;` 했지만
```
SELECT *
FROM weather w1
INNER JOIN weather w2
on w1.recordDate = DATE_ADD(w2.recordDate, INTERVAL +1 DAY)
WHERE w1.temperature < w2.temperature ;

<result>
| id | recordDate | temperature | id | recordDate | temperature |
| -- | ---------- | ----------- | -- | ---------- | ----------- |
| 3  | 2015-01-03 | 20          | 2  | 2015-01-02 | 25          |

```
- 잉? 왜 반대로 나오지?
- 다시! step2의 결과를 눈을 크게 뜨고 보자!

```
SELECT *
FROM weather w1
INNER JOIN weather w2
on w1.recordDate = DATE_ADD(w2.recordDate, INTERVAL +1 DAY);

<result>
| id | recordDate | temperature | id | recordDate | temperature |
| -- | ---------- | ----------- | -- | ---------- | ----------- |
| 2  | 2015-01-02 | 25          | 1  | 2015-01-01 | 10          |
| 3  | 2015-01-03 | 20          | 2  | 2015-01-02 | 25          |
| 4  | 2015-01-04 | 30          | 3  | 2015-01-03 | 20          |
```
- `| 2  | 2015-01-02 | 25          | 1  | 2015-01-01 | 10          |`
- 뭔가 이상하지 않나?
- 왼쪽이 1월1일이 아닌 2일부터 시작한다.
- 여기서 나의 오개념은 `ON w1.recordDate = DATE_ADD(w2.recordDate, INTERVAL +1 DAY);` 쿼리의 잘못된 해석으로부터 시작된다.
- 'ON쿼리문'의 진짜해석: w2.recordDate의 날(Day)에 +1을 더한 날짜가 w1.recordDate의 날짜가 된다.
```
ON w1.recordDate = DATE_ADD(w2.recordDate, INTERVAL +1 DAY);

<처리과정>
(1) 'w2의 날짜' -> 2015-01-01 (기준일)
(2) 'w2의 날짜'에 +1 더한 '날짜' -> 2015-01-02
(3) '2015-01-02'을 'w1의 날짜'로 한다.
즉, 아래와 같이 처리하겠다는 의미임
| id | recordDate | temperature | id | recordDate | temperature |
| -- | ---------- | ----------- | -- | ---------- | ----------- |
| 2  | 2015-01-02 | 25          | 1  | 2015-01-01 | 10          |

그래서 w1쪽의 날짜가 +1을 더한 오늘이고
w2쪽은 날짜가 w1에 비해 -1인 어제가 된다.
그래서 where문의 조건절은 오늘 기온이 어제 기온보다 높은 경우 이므로
w1.temperature(오늘) > w2.temperature(어제) 이 된다. 

```
